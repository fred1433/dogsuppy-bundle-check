        The same check, every morning

        The sheet at the top lays out all 19 bundles so each sum can be followed. In BigQuery the check is a set of views that return only what does not add up: one row per problem, nothing when all is well, the same columns in each (check_name, severity, store, key, expected, actual, delta, evidence_url, read_at). A rule that cannot run on a row returns it as not_checked, never as a pass. On the 23 Nov snapshot:

        checks_bundle_compare_atstruck price against the products the description lists4 rows

        What was tested, and how
        
        
          
          
        • A clean test catalogue returns 0 rows; each of 8 trapped catalogues returns exactly its one row (stale struck price, 10 cents off, struck price equal to the price, a bundle with no readable contents, a jar that cannot be priced, and more).
          • 
          
        • Change the data: Dental Bright on dogsuppy.com at €37.70 instead of €37.60 adds 4 rows, the 4 bundles there that hold it (8 in all with the Italian ones). The Italian jars at €29.90 leave 0 rows.
          • 
          
        • Break the SQL on purpose, 14 ways (drop the quantity, widen the tolerance to 50 cents, ignore the "or Dental Liquid" choice, count gifts at 0.00): the tests catch 14 of 14.
          • 
          
        • Not run here: BigQuery and Google Sheets, and no Google account was used. The BigQuery copy is the same SQL with dataset names added; it parses in BigQuery's dialect but has not been executed. The Apps Script is provided to install: it fills an Exceptions tab from checks_all each morning, with times in Europe/Brussels, amounts to two decimals and SKU keys kept as text, and colours the rows that were not there the day before.
